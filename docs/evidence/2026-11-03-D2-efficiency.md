# D2 证据：效率基线（Agent 端到端 vs 裸工具链）

- 日期：2026-11-03
- 目标：给「Agent 到底省了什么」一个可复现的数字基线，而不是只讲流程。
- 重要边界先说：**本证据测的是机器耗时（wall clock），不是真人手剪耗时**。真人手剪基线需要用户测试，本轮未做，下文不主张「比人工快 N 倍」。

## 方法

同一素材 `output/demo/speech_long.mp4`（48.16s，TTS 中文口播，含 4 处静音停顿），执行 3 个标准任务：

1. **S001 静音裁剪**：检测静音 → 生成裁剪区间 → 渲染成片
2. **S006→S002 语音转写 + 字幕校对**：抽音轨 → Whisper 转写 → 写 SRT → 标点/折行修正
3. **S005 调色预设 + 对比图**：读 `color001` 资产 → ffmpeg 滤镜链渲染成片 → 生成一帧前后对比图

每侧重复 5 次取中位数：

- **Agent 侧**：`python -m clip_agent run ...`（含意图路由、执行、预览报告、HTML 报告、埋点）
- **裸工具链侧**：直接调用相同的 ffmpeg / mlx-whisper 工具与相同的算法函数，不经过 Agent 层
- Whisper 模型已缓存，测量时设 `HF_HUB_OFFLINE=1` 避免网络检查抖动

复现命令：

```bash
# 生成真实语音素材（macOS say + ffmpeg）
.venv/bin/python scripts/make_speech_fixture.py --long

# 跑基线（5 次中位数）
.venv/bin/python scripts/bench_efficiency.py \
  --media output/demo/speech_long.mp4 --runs 5 --offline \
  --json docs/evidence/artifacts/2026-11-03-d2/bench.json
```

## 结果（2026-11-03，macOS arm64 / Python 3.13.12 / ffmpeg 9.0.2）

| 任务 | Agent 端到端（中位数） | 裸工具链（中位数） | 编排开销 |
|---|---|---|---|
| S001 静音裁剪 | 0.694s | 0.669s | +0.025s（+3.7%） |
| S006→S002 转写+校对 | 1.661s | 1.620s | +0.041s（+2.5%） |
| S005 调色预设+对比图 | 3.028s | 2.784s | +0.244s（+8.8%） |
| **合计** | **5.383s** | **5.073s** | **+0.310s（+6.1%）** |

解读：

- Agent 层的编排开销很小：**合计 +6.1%**，主要来自 S005 的额外预览/报告开销（+0.244s）。
- 这 6.1% 买到的是：指令路由、步骤编排、落盘方案（`silence_cut.json`/SRT/参数）、预览报告 `report.md`、HTML 报告、埋点数据、资产/组合复用能力——这些裸命令都不产出。
- 单次任务耗时都在秒级，真正的时间大头是**人找素材、判断、改错字、反复导出**，机器执行不是瓶颈；所以效率叙事应落在「操作单元减少 + 预览确认成本降低」，而不是「编码快几倍」。

## 操作单元对照（协议计数，未实测人工时间）

计数协议：一次点击、一次输入、一次导出各计 1 个操作单元；等待渲染不计；同一面板内拖动 4 个参数计 4 次。

| 任务 | 手工剪映（操作单元） | Agent（操作单元） |
|---|---|---|
| S001 静音裁剪 | 导入/拖轨/选中/智能分割/选段/删除/导出 ≈ 7 | 1 条命令 + 0 次手动删除 |
| S006→S002 字幕 | 选中/智能字幕/识别/逐条改错字（≥5）/样式（3）/导出 ≈ 11–13 | 1 条命令 + 1 次确认（本基线 `--yes` 自动确认） |
| S005 调色+对比图 | 选中/调节面板/4 参数/前后对比/导出 ≈ 9 | 1 条命令 + 1 次确认 |
| **合计** | **≈ 27–29 个操作单元 + 3 次导出** | **3 条命令（或 combo 资产 1 条）+ 确认** |

本基线 15 次 Agent 运行、15 次裸工具链运行，**0 次人工干预/重试**（D1 已修复的 S006 渲染协议 bug 不计入本次测量）。

## 不能证明什么（如实记录）

- 没有测真人手剪耗时：上表「操作单元」是按协议数出来的，不是秒表测出来的；真人熟练度、软件版本、素材复杂度都会显著影响时间。
- 没有做用户效率实验（A/B 真人），因此**不能**声称「效率提升 X%」。
- 只测 1 条 48s 素材、1 台 M 系列 Mac；长视频、多轨、4K 场景未覆盖。
- Agent 侧命令仍需人写对指令；指令理解失败时的返工时间未计入。

## 下一步（留给 D5 文档与后续）

- 若要支撑「比手工快」的结论，需要 3–5 位创作者的计时实验（同一素材、同一目标，手工 vs Agent），记录完成时间、操作次数、返工次数。
- 当前证据只支撑：**机器执行秒级、Agent 编排开销 +6.1%、操作单元从约 27–29 降到 3 条命令**。
