# D3｜剪映草稿导出最小版：真机导出 + 结构校验

> 日期：2026-11-03 · 对应计划：D3–D4（grill Round 3 批准）· 版本：V1.2 最小版
> 结论：**Mac 上成功生成可被剪映读取的草稿目录**（pyJianYingDraft 0.3.1，Python 3.13）。
> 未验证项：在 Windows 版剪映中实际打开/导出（本机无 Windows），仅做结构校验与库级 round-trip。

## 2. 实现

- `clip_agent/export/jianying.py`
  - 纯函数 `build_draft_plan(preview, workdir, media, ...)`：S001 `cut_time_list`（无则 S003 `highlight_segments`，再无则整段素材）→ 视频轨片段；S002 `fixed.srt` 按裁剪点重映射到成片时间轴；S004 `bgm_aligned.m4a` → BGM 轨；S005 调色只记录参数映射。
  - 写入层 `write_draft(plan, out_dir, replace=False)`：调用 pyJianYingDraft 生成 `draft_content.json` / `draft_meta_info.json`，同一素材只建一个材质实例；草稿旁写 `<草稿名>.clip_agent.json`（完整计划 + 调色映射）。
  - 无 `[jianying]` 依赖时抛 `JianyingExportError`，提示 `pip install -e ".[jianying]"`，不影响核心链路。
- `clip_agent/__main__.py`：新增 `export-jianying <run_dir>` 子命令（`--media/--bgm/--out/--name/--duration/--replace/--dry-run/--json`）。
- `clip_agent/preview/snapshot.py`：`preview.json` 新增 `media` / `bgm` 字段，供导出时自动定位素材。
- `pyproject.toml`：`jianying = ["pyJianYingDraft>=0.3.1"]`。
- `tests/test_jianying_export.py`：10 项测试（映射/降级/结构/CLI dry-run；无第三方库时结构用例自动 skip）。

## 3. 真机运行

```bash
# 1) 真实 run：S006 转写 → S002 校对 → S001 静音裁切（combo003）
python -m clip_agent run --combo combo003 --media output/demo/speech_long.mp4 \
  --set asr_model=mlx-community/whisper-large-v3-turbo --yes --workdir output/run_d3_jianying

# 2) 先 dry-run 看计划
python -m clip_agent export-jianying output/run_d3_jianying --dry-run

# 3) 写入草稿
python -m clip_agent export-jianying output/run_d3_jianying --out output/jianying_drafts
```

计划结果：素材 48.160s → 裁剪保留 5 段（静音段被去掉）→ 成片 42.489s；字幕 5 条映射到成片时间轴。

## 5. 边界（如实记录）

1. **macOS / Linux 只能生成草稿，不能自动导出视频**；需在 Windows 版剪映打开并导出（pyJianYingDraft 官方限制；自动导出需 Windows + 剪映 ≤6.8）。
2. **本次未在 Windows 剪映中实际打开**——验收只到「草稿目录结构正确 + 库可回读」；开箱验证是待办（有 Windows 环境时补）。
3. 调色不自动套用：只把「亮度/对比度/饱和度/色温」映射写入 `.clip_agent.json`，不读写剪映私有加密数据。
4. 字幕映射会在裁剪点处裁切/跳过跨静音句；S002 只修标点与折行，同音错字仍会带进草稿（D1 已记录）。
5. BGM 依赖 S004 渲染产物 `bgm_aligned.m4a`；没有该文件时用 `--bgm` 原始文件整段（未循环对齐）。
