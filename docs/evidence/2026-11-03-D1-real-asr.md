# D1 证据：真实语音素材 + S006 真机转写

- 日期：2026-11-03
- 目标：消解「S006 只在桩后端上测过」「演示素材是合成正弦波」两个质疑。
- 结论：**S006 已在真实 mlx-whisper 后端上跑通 S006→S002 链式流程**；同时发现并修复一个真实渲染协议 bug。转写质量边界如实记录：large-v3-turbo 在 47.9s 中文口播上的字符错误率（CER）为 5.52%，small 为 11.04%。


## 素材生成（可复现）

本机无用户自录素材，按 Round 3 批准的 Q1=B 用 macOS 中文 TTS 生成 30–60s 口播，并在句中插入 `[[slnc]]` 停顿，给 S001 留出真实静音段：

```bash
TEXT='大家好，今天演示剪辑辅助 Agent 的完整流程。[[slnc 1200]] 先识别口播里的静音片段，把停顿自动裁掉，让节奏更紧凑。[[slnc 1000]] 然后校对字幕，按语义重新断句，最长每行十六个字。[[slnc 900]] 接着给画面加一层清冷胶片感，并生成前后对比图，方便确认效果。[[slnc 800]] 最后把这些步骤保存成组合资产，下次一键复用。整条链路都在本地完成，不上传素材，也不依赖额外服务。效果不满意时，可以只预览，不落盘。这就是今天要展示的核心能力。'
say -v Tingting -o output/demo/speech_long.aiff "$TEXT"
ffmpeg -y -hide_banner -f lavfi -i 'color=c=0x1a1a2e:s=1280x720:r=25' -i output/demo/speech_long.aiff \
  -shortest -c:v libx264 -preset veryfast -pix_fmt yuv420p -c:a aac -b:a 128k output/demo/speech_long.mp4
```

产物：`output/demo/speech_long.mp4`，时长 **47.88s**（TTS 合成语音，非真人；演示与文档中均如实标注）。

## 执行命令

```bash
# small（默认模型）
HF_ENDPOINT=https://hf-mirror.com HF_HUB_DISABLE_XET=1 \
  .venv/bin/python -m clip_agent run "先语音转写，再校对字幕" \
  --media output/demo/speech_long.mp4 --yes --workdir output/run_d1_asr

# large-v3-turbo（用 --set 覆盖 S006 的 asr_model 参数）
HF_ENDPOINT=https://hf-mirror.com HF_HUB_DISABLE_XET=1 \
  .venv/bin/python -m clip_agent run "先语音转写，再校对字幕" \
  --media output/demo/speech_long.mp4 \
  --set asr_model=mlx-community/whisper-large-v3-turbo \
  --yes --workdir output/run_d1_asr_turbo_cached
```

路由结果：规则路由命中「S006 语音转写生成字幕 → S002 字幕批量校对与样式统一」，两条步骤串行执行，S002 自动消费 S006 产出的 `transcribed.srt`。

## 结果

| 指标 | small（`whisper-small-mlx`） | large-v3-turbo |
|---|---|---|
| 模型体积（本地缓存） | 470 MB | 1.5 GB |
| 首次下载耗时 | 约 0s（镜像命中） | **12m27s**（1.5 GB） |
| 缓存后 S006 推理耗时 | **2.19s**（≈21.9× 实时） | **2.19s**（≈21.9× 实时） |
| 识别段数 | 5 | 5 |
| CER（转简体、去标点后，编辑距离/参考字数） | **11.04%**（18/163） | **5.52%**（9/163） |
| 输出字形 | 繁体为主 | 简体 |
| 明显错例 | 「识别口播里」→「使別口玻璃」；「校对」→「較對」；「一键复用」→「一件附用」；「只预览」→「知欲攬」 | 「Agent」→「Ajit」；「口播里」→「口玻璃」；「只预览」→「知预览」 |

CER 计算：参考文本为上面的 TTS 原文；OpenCC `t2s` 转简体、转小写、去标点与空格后，用字符级 Levenshtein 距离除以参考字数。OpenCC 仅用于本证据分析，**未加入项目依赖**。

质量结论（如实记录）：

- 5 段断句与时间戳正确，S006→S002 链路可用，S002 能修标点/折行，但**修不了同音错字**（如 Ajit / 口玻璃），这是当前小模型的真实边界。
- turbo 质量明显更好（CER 减半），但首次下载 1.5 GB；两者缓存后推理都约 2.2s，**模型大小对推理耗时影响不大**，对首次启动成本影响大。
- 若要上生产，应加**领域热词/initial_prompt** 或换更大模型，并做人工校对环节——已列入 backlog，不在 D1 范围。

## 过程中发现并修复的 bug

真实运行暴露出移植代码的协议不一致：调度器调用 `skill.render(..., on_progress=...)`，而 S006 的 `render()` 未接收该参数，导致：

```
⚠ S006 渲染失败：TranscribeSkill.render() got an unexpected keyword argument 'on_progress'
```

修复：`clip_agent/skills/s6_transcribe.py` 的 `render(self, ctx, params, outputs, on_progress=None)`；新增回归测试 `tests/test_transcribe.py::test_s6_render_accepts_progress_callback`。修复后全量 **84 passed**，S006 渲染不再报错。

- 语音为 **TTS 合成**，非真人录音；无环境噪声、无口音、无多人对话，真实场景 CER 预计更高。
- 只测了 1 条素材、1 种语言（zh）、2 个模型；不构成模型选型结论。
- 真人手剪基线未测（D2 处理，且会明确区分「机器耗时」与「人工耗时」）。
- 安装 `mlx-whisper` 会把 torch/mlx 等装进 `.venv`，但项目 `dependencies` 仍为空，核心零依赖不受影响。
