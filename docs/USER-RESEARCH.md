# 创作者需求案头研究（汇总）

> 方法：公开网络检索（2026-11-02），原始素材与逐条来源见 [user-research-raw.md](user-research-raw.md)。
> 性质：**桌面研究，不是一手访谈**——用于形成需求假设与证据链；样本受公开内容偏倚影响（登录墙平台未覆盖），不能替代验证。访谈验证计划见 [RETRO.md](RETRO.md) 缺口 1。

## 核心结论

1. **重复劳动是创作者最大的时间黑洞**：未建流程的创作者约 **70% 制作时间**花在重复性手工任务上，字幕/切条为最大耗时项（厂商博客数据，需交叉验证）。
2. **五个 Skill 对应的痛点均有公开证据，强度分层**：S001 静音 / S002 字幕**证据最强**；S004 BGM 对齐中等；S003 高光 / S005 调色有需求信号但直接吐槽证据偏弱（剪映已有预设保存/色彩匹配能力）。
3. **头部 vs 新手诉求分层明确**：专业向要批量、风格统一、交付稳定、改稿管控；新手向要模糊指令、一键出片、功能找得到。
4. **AI 的信任边界 = 任务性质**：AI 适合有明确正确答案的任务（降噪、色彩匹配、字幕初稿、去静音），不适合判断性任务（在哪剪、停顿多长）。「改一处坏一处」与不可编辑是主要不信任来源——**印证了预览确认、参数可调、可撤销的设计**。
5. ⚠️ **竞品事实修正**：剪映 2026-04 已上线 Skill 化 AI 助手，2026-09 专业版「剪映助手」支持自定义 Skills——"剪映没有可编排 Agent Skill"的叙事已不成立。项目定位已同步修正为「官方验证方向 + 第三方差异化」，见 RETRO §3。

## 痛点 → Skill 映射与证据强度

| 痛点主题 | 关键证据 | 强度 | 对 Skill 的含义 |
|---|---|---|---|
| 静音/停顿删除 | 36氪实测「智能剪口播」省时但误删有意停顿；官方已有该功能；批量场景手动拖动不可行 | **强** | S001 优先；padding 保留 + 预览确认是必要设计（已落实） |
| 字幕校对 | App Store 评论「错别字且不可修改」；PC 专业版不能双击编辑/不能导出 SRT；核对是独立耗时工序 | **强** | S002 优先；SRT 导出 + 批量规则修正 + 样式统一正对痛点 |
| 高光/素材筛选 | 挑片段 4–6h / logging 2 天（厂商博客）；界面新闻剪辑工时链路；**国内 PC 端直接证据弱** | 中（方向强、一手弱） | S003 保留但表述谨慎；V1.1 多模态精排 |
| BGM 卡点/对齐 | 自动踩点后仍需人工补点；故障诊断教程大量存在 | 中 | S004 差异点在「BGM 与高光总长联动」——S003→S004 编排 |
| 调色/风格统一 | 官方已有预设保存/色彩匹配；专业工作流靠 SOP 维持统一；批量调色吐槽少 | 中弱 | S005 差异在**资产库形态**（版本/组合/工作流串联），不宣称"剪映没有" |
| 批量产能 | 70% 重复劳动；剪映批量能力在几十上百条时有限；改稿占用预留工时 116% | 强（趋势） | Agent + 资产库的产品空间；批量处理是头部刚需 |

## 头部 vs 新手诉求分层

| 人群 | 诉求 | 对应产品路径 |
|---|---|---|
| 头部/专业 | 批量处理、多轨道、风格统一、交付稳定、改稿管控 | 组合方案（多 Skill 流水线）、资产库、参数可复制 |
| 新手/初阶 | 功能找得到、模糊指令、一键出片 | 规则路由 + LLM 意图解析，自然语言直达单 Skill |

## 人机边界的行业证据

- 「AI 适合有明确正确答案的任务，不适合判断性任务」——与本项目 Skill 清单的边界**完全一致**；
- 「改一处坏一处」、黑盒、不可编辑是主要不信任来源——支持预览确认 + 参数可调 + 时间戳方案（用户自己执行）；
- 剪映官方 FAQ「智能粗剪仅是提效起稿，仍需精修」——可直接引用的官方口径。

## 对产品的直接影响

1. **演示与简历优先级**：S001/S002 为主打（证据强、演示直观）；S003→S004 联动演示；S005 强调资产库而非滤镜本身；
2. **新 Skill 候补（V1.1+）**：多平台导出预设（抖音/小红书/视频号三套）、素材整理/打标、封面/包装模板、混音平衡（BGM 低于旁白 20%）、字幕翻译；
3. **定位修正**：见 RETRO §3（官方已 Skill 化，本项目做第三方差异化验证）。

## 证据薄弱清单（如实标注）

1. 中文社区对「批量调色/风格统一麻烦」的直接一手吐槽缺失（多为教程/营销号标题）；
2. 国内剪映 PC「精彩片段/高光」功能缺用户实测（国际版 CapCut 与字节云 API 为间接佐证）；
3. 头部创作者（MCN/团队）一手工作流资料少，量化多来自海外厂商博客（有利益相关）；
4. 剪映助手「自定义 Skills」2026-09 刚发布，实际体验评测极少；
5. 小红书/抖音等登录墙平台未抓取，可能遗漏创作者一手吐槽。
