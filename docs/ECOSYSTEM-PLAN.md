# 创作者资产生态规划（V1.1+）

> 对齐 JD 职责 ③：「推进预设、Skill 等创作知识的积累沉淀和分发使用，完善创作者生态」。
> 本文回答三个问题：资产怎么**被创造**、怎么**被发现**、怎么**被回报**。
> 前置阅读：`docs/RETRO.md` 第 6 章缺口 2。

## 0. 一页结论

生态不是"做一个资产市场"，而是让优秀的工作参数**从个人经验变成可流通的公共品**。路径分三段：

1. **沉淀**（V1.0 已实现）：本地资产库——预设、组合方案、版本回滚、收藏；
2. **流通**（V1.1）：资产导出/分享码/导入即用——先验证"有人愿意分享、有人愿意用"；
3. **激励**（V1.2）：社区榜单 + 创作者回报机制——验证"分享有人用"之后再谈"分享有收益"。

北极星指标候选：**周复用资产数**（一个资产被不同用户应用在不同素材上的次数/周）——它同时反映供给质量与需求匹配，且天然抗刷（复用必须发生在真实素材处理中）。

## 1. 现状与缺口

| 能力 | V1.0 现状 | 缺口 |
|---|---|---|
| 沉淀 | `AssetLibrary`：调色预设/字幕模板/Skill 组合，版本回滚、收藏、搜索 | 无跨设备同步 |
| 流通 | ❌ 无 | 导出/导入、分享码、依赖声明 |
| 发现 | ❌ 无 | 广场、榜单、标签体系 |
| 激励 | ❌ 无 | 创作者主页、付费/分成 |
| 质量信号 | 埋点已采集采纳率/二次修改率（本地） | 质量分未聚合、不可见 |

**判断**：先做流通（P1），再做发现（P2），最后做激励（P3）——没有真实资产流动之前，榜单和分成都是空转。

## 2. 生态对象模型

**资产类型（按 JD 的"预设、Skill"归类）：**

| 类型 | 内容 | 版权风险 | 差异化 |
|---|---|---|---|
| 调色预设 | eq/colorbalance 参数或 LUT | 低（参数无版权） | 剪映调节面板数值映射，跨工具可用 |
| 参数包 | 某个 Skill 的参数配置（如"口播静音裁切：-35dB/0.8s/留 0.15s 余量"） | 无 | Skill 生态独有——这是与模板市场错位竞争的核心 |
| 组合方案 | 多 Skill 串行流水线（如"口播净化 = S001→S002→S004"） | 低 | 类似"工作流模板"，行业里少见 |
| 字幕模板 | 样式参数（字体/字号/描边/位置） | **高：字体授权** | 仅存样式参数，不分发字体文件 |

**资产属性（在现有 Asset 模型上扩展）：**

- `dependencies`：依赖哪些 Skill 及最低版本（资产失效的第一原因）；
- `scenario_tags`：适用场景（口播/剧情/vlog/游戏/带货）；
- `quality_score`：由采纳率×复用次数聚合，榜单排序依据；
- `share_code` / `license`：分享标识与使用许可（免费/署名/付费）。

## 3. 分享链路设计（P1，技术形式）

- **导出**：单资产 → `.clipasset` 文件（JSON + 元数据，含依赖声明与版本号）；
- **分享码**：短码（如 `CA-7F3K2`）关联导出内容，可贴进创作者社群；
- **导入即用**：校验依赖（缺 Skill 版本时明确提示"需要 S004 ≥ v1.1"）、预览参数差异、一键加载到本地库；
- **组合方案**：导入后自动映射到对应 Skill 调用链，参数缺失时回退默认值并高亮提示。

设计原则：**资产是参数，不是代码**——不引入可执行脚本，规避安全与兼容问题。

## 4. 发现机制（P2）

- **资产广场**：按场景标签 + 质量分排序；「官方精选」与「社区热门」两个取入口径；
- **榜单防刷**：复用次数以"独立用户 × 不同素材"去重计权，异常模式（短时间内同设备批量复用）降权；
- **创作者主页**：作品列表、被复用次数、采纳率（公开口径与评测体系一致）。

## 5. 质量与治理

1. **质量信号**：采纳率（用户确认应用）优先于下载量——下载不产生价值，采纳才产生；
2. **版本与兼容**：资产声明 Skill 版本；断代资产自动标记"需更新"；
3. **合规红线**：字体（字幕模板只存样式参数，不携带字体文件）、音乐（BGM 相关参数不打包音频）、肖像素材不进入资产；
4. **低质治理**：零采纳资产 90 天降权；社区举报 + 人工抽审；
5. **与官方生态的关系**：官方体系内已有两层——剪映模板广场（成品模板）与剪映助手自定义 Skills（2026-09，内建 Skill 生态）。第三方生态的机会在**跨工具、本地可审、参数资产标准化**；资产格式向官方 Skill 形态对齐以降低迁移成本，远期评估合作接入。

## 6. 冷启动策略

| 步骤 | 动作 | 供给/需求来源 |
|---|---|---|
| ① 种子 | 需求研究中的 5–8 位访谈创作者转化为首批分享者 | 已有触点 |
| ② 标杆 | 官方自建 20 个标杆资产（3 个预设 + 口播净化等组合方案） | 团队自产 |
| ③ 榜单 | 用真实复用数据跑首期榜单（哪怕只有 30 个资产） | 冷启动数据 |
| ④ 开放 | 分享入口全量开放 + 创作者激励预告 | 自然增长 |

## 7. 指标

| 层级 | 指标 | 目标（P2 阶段） |
|---|---|---|
| 供给 | 有效资产数（≥3 次复用）、周新增 | +10/周 |
| 需求 | 资产导入→应用转化率 | ≥50% |
| 北极星 | 周复用资产数 | 阶段目标按冷启动数据定 |
| 二创 | 导入后修改参数的比例 | 30–60%（过低说明同质，过高说明不够贴合） |
| 生态健康 | 零采纳资产占比 | <30% |

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 资产同质化、低质泛滥 | 质量分排序 + 零采纳降权 + 官方精选 |
| 字体/音乐版权纠纷 | 资产只存参数；类目白名单；用户协议明确责任 |
| 榜单作弊 | 独立用户×不同素材去重计权；异常检测降权 |
| 剪映官方模板/Skill 生态覆盖 | 错位定位（跨工具/本地/可审）；资产格式与官方 Skill 形态对齐，保留合作接入路径 |
| 资产格式随 Skill 演进断代 | 依赖声明 + 版本校验 + 一键升级提示 |

## 10. 里程碑

- **M2（V1.1）**：导出/分享码/导入即用上线；20 个标杆资产；首期榜单跑通；
  **成功标准**：种子用户 ≥30% 保存或复用至少一个导入资产。
- **M3（V1.2）**：创作者主页 + 精选机制 + 付费/分成评估；
  **成功标准**：周复用资产数连续 4 周正增长。
